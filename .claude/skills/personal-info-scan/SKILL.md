# personal-info-scan

## これは何のためのスキルか

このリポジトリ(dotfiles)は OSS 公開を前提に、機密情報・個人情報や、特定の
文脈が分かる記述を一切含めない方針を徹底している([CLAUDE.md](/CLAUDE.md) 参照)。この方針が
実際に破られかけたのは、真新しいファイルを書くときではなく、**既存の実機設定を
「良さそうだから」とそのまま取り込もうとしたとき**だった。

実例: `~/Configs/codex/global/config.toml`(「おすすめ設定」として自分で書いた
はずのファイル)に、後から実運用で `[projects."/Users/<username>/..."]` のような
実ユーザー名入り絶対パス・実プロジェクト名が大量に追記されていた。ファイルの
見た目(コメント付きの整然とした設定)だけでは汚染に気づけない。

このスキルは、そうした「取り込み候補ファイル」を機械的に一次スキャンし、
危険信号を早期に洗い出す。

## 検出対象

- 機密情報らしきパターン(APIキー・トークン・秘密鍵など。`.githooks/pre-commit`
  と同種のパターン)
- 実行環境の `$USER` を含む絶対パス(`/Users/<user>/...` 等)
- メールアドレス

**検出できないもの(自動化の限界)**: プロジェクト名・会社名・個人の生活が
分かる記述、特定の文脈を示す固有名詞などは機械的に検出できない。特に
`commands/*.md` のようなプロンプト系ファイルは、このスキルが「クリーン」と
判定した後でも**必ず全文を目視で読む**こと(CLAUDE.md 最重要ルール)。

## ワークフロー

### 1. スキャンスクリプトを実行する

```sh
.claude/skills/personal-info-scan/scripts/scan.sh <ファイルまたはディレクトリ> [...]
```

複数ファイル・ディレクトリを一度に渡せる。ディレクトリを渡すと配下の全ファイルを
再帰的に検査する(バイナリファイルは自動スキップ)。読み取り専用で、対象ファイルを
一切変更しない。

### 2. 結果をユーザーに提示する

- 「機密疑い」「実ユーザー名パス」「メールアドレス疑い」のいずれかが出た場合は、
  該当ファイルを**移行候補から除外する**か、該当箇所を削ってから改めて確認するかを
  ユーザーに確認する。**該当箇所をそのまま報告メッセージに引用しない**(報告自体が
  漏洩経路にならないよう、ファイルパスと行番号のみ伝え、値は「実ユーザー名を含む
  パスが12箇所」のように件数・種別で要約する)。
- 何も検出されなかった場合でも「機械的検出はクリア。プロンプト系ファイルは全文を
  目視で確認すること」と必ず添えて、自動判定を過信させない。

### 3. 移行は必ず確認を取ってから

このスキル自身はファイルの取り込み・削除・修正を行わない。安全と判断した
ファイルについても、実際に `home/` や `templates/` へコピーする操作はユーザーの
明示的な承認を得てから実行する([破壊的操作は確認を取ってから](/CLAUDE.md)の
方針に従う)。

## 注意点

- `$USER` 判定はこのスクリプトを実行しているマシンのユーザー名に基づく。
  複数マシンの設定を扱う場合、それぞれのマシンで実行するか、対象ユーザー名を
  意識して結果を読む。
- gitleaks が導入済みでも、このスキルの対象はリポジトリに入れる**前**の
  外部ファイルなので、既存の pre-commit フックとは独立して実行する必要がある。
- スキャン結果に何も出ないことは「安全」の証明ではなく「機械的パターンには
  一致しなかった」というだけ。最終判断は必ず人間(ユーザーまたはこのスキルを
  呼び出したエージェント自身の目視確認)が行う。

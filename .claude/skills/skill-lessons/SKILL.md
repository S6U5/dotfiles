# skill-lessons

## これは何のためのスキルか

`.claude/skills/` には複数のスキルがあり、それぞれ skill-creator を使って作成・評価・
改善されている。この過程で得られる教訓(AI が繰り返し陥りがちな間違い、eval 設計の
落とし穴、SKILL.md の書き方で効果があった/なかった工夫など)は、個別のスキルの
SKILL.md に埋め込むと散逸し、次に別のスキルを作るときに再発見するコストがかかる。

このスキルは、それらの教訓を `LESSONS.md`(このスキルディレクトリ直下)に一箇所に
集約し、スキル横断で参照・蓄積できるようにする。対象範囲はこのリポジトリの
`.claude/skills/` 配下の全スキル共通。

## いつ使うか

- skill-creator での eval 実行・グレーディング・SKILL.md 改訂・トリガー最適化などの
  作業が完了した直後。作業中に「これは他のスキルを作るときにも役立ちそうだ」と思う
  非自明な発見があった場合は、指示を待たずに記録を提案すること。
- ユーザーから明示的に記録を依頼されたとき。
- 過去の教訓を参照したいとき(新しいスキルを設計する前に LESSONS.md に関連する
  カテゴリが無いか確認するとよい)。
- 単なる誤字修正、既存の教訓の言い換えに過ぎない変更には使わない。

## 記録の手順

1. **既存の LESSONS.md を確認する**: 同じカテゴリ・同じ教訓が既に無いか grep する。
   重複があれば新規追記ではなく、既存項目の「関連」欄に一言足す程度に留める
   (過去のエントリ本文は書き換えない。ADR と同じ考え方: 記録は基本的に追記のみ)。
2. **候補エントリを起草する**: 下記フォーマットで日付・カテゴリ・本文を書く。
3. **ユーザーに提案し、承認を得てから追記する**: 起草した内容をそのままユーザーに
   提示し、追記してよいか確認する(自動で黙って書き込まない)。ユーザーが直すと
   言った内容だけを反映する。
4. **公開リポジトリであることに注意する**: このリポジトリは OSS として公開予定
   (`CLAUDE.md` 参照)。LESSONS.md にも同じ制約が適用される。個人的な事情や、
   特定の会社名・プロジェクト名などが混ざっていないか、追記前に必ず精査する。

## フォーマット

`LESSONS.md` に見出しレベル2(`##`)で追記する。1エントリ1見出し。

```markdown
## YYYY-MM-DD — <カテゴリ>: <一行タイトル>

<何が起きたか(具体的な事象・観測)>

**教訓**: <そこから導かれる、次に活かせる具体的な指針>
```

カテゴリは自由記述だが、既存の粒度に合わせる。目安:

- `eval-methodology` — eval の実行環境・手順そのものに関する落とし穴(サンドボックス分離、
  再現性の確保など)
- `eval-design` — assertion / eval prompt の設計品質(discriminating かどうか等)
- `skill-writing` — SKILL.md の指示の書き方で効果があった/なかった工夫
- `agent-orchestration` — サブエージェントを並列実行・グレーディングする際の運用上の注意

新しいカテゴリが必要なら作ってよいが、既存カテゴリで表現できないか先に確認する。

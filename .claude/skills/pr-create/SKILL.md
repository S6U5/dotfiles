# PR を作る

## 手順

1. **ブランチを確認する。** main で作業していたら、先にブランチを切る(pre-commit フックが main への直コミットを弾くが、push 前に気づく方が手戻りが小さい)。
2. **`./scripts/lint.sh` を通す。** CI で落ちると往復が増える。
3. 本文を書く(下記の基準)。
4. **本文をスキャンする**(下記のコマンド)。
5. `gh pr create` で作成する。
6. `gh pr checks <番号>` で CI の通過を確認する。
7. マージは squash。

## 本文に書くもの、書かないもの

**書く** — 何を変えたか、なぜそう決めたか、影響範囲。判断の根拠(公式ドキュメントの記述、実際に動かして分かったこと)。レビューする人が必要とするもの。

**書かない** —

| | 例 | なぜ |
|---|---|---|
| 実マシンの状態 | 「`~/.claude/skills/` に旧実体が残っている」「設定ファイルが 19:52 に作り直されている」 | PR は公開される。手元の環境で何が起きているかは読む人に不要 |
| 作業過程 | 「3回テストして4件の誤りを見つけた」「イテレーションを回した」 | セッションの文脈。結論と根拠だけあればいい |
| Claude の痕跡 | セッション URL、`Co-authored-by: Claude`、`Generated with Claude Code` | AGENTS.md の方針。作業文脈を残さない |

**紛らわしい区別**: 配布先のパスを説明するのは問題ない。「`~/.config/zsh/.zshrc` は `home.activation` が生成する」は**設計の説明**であって実マシンの状態ではない。一方「`~/.codex/config.toml` を実機からコピーした状態だった」は実環境の話なので書かない。

書くのは**リポジトリがどうなるか**であって、**手元がどうなっているか**ではない。

## 本文をスキャンする

作成前に必ず実行する。下書きをファイルに書いてから通す。

```sh
grep -nEi 'claude\.ai/code|Co-authored-by|Generated with|Claude-Session' 下書き.md   # Claude の痕跡
grep -nE '実機|手元の|今日|昨日|先ほど|[0-9]{1,2}:[0-9]{2}' 下書き.md                  # 実環境・作業タイミング
grep -nE 'イテレーション|回テスト|件の誤り|何回|セッション' 下書き.md                  # 作業過程
grep -nE '/Users/|/home/[a-z]' 下書き.md                                              # 実ユーザー名入りパス
```

ヒットしたら消すか書き換える。**既存 PR を点検するときも同じコマンドを本文に対して通す**(`gh pr view <番号> --json body --jq .body` で取れる)。

## 本文の形

見出しは内容に合わせてよいが、末尾に確認事項を置く。既存 PR がこの形式で揃っている。

```markdown
## 概要

(何をする PR か。1〜3文)

## 変更内容

- (箇条書き)

## 確認事項

- [x] 機密情報(APIキー・トークン・パスワード)を含んでいない
- [x] プライベートなパス・個人情報(実ユーザー名、メール、所属など)を含んでいない
- [x] 個人的なこと・特定の文脈が分かる内容を一切含んでいない(プロンプトテンプレートは特に全文精査した)
- [x] 既存コマンドと名前が衝突していない
- [x] 依存ツールが無い環境でも壊れない
- [x] 対象 OS(WSL / macOS / Linux)以外で不要なものが定義されない
- [x] シェルスクリプトを変更した場合: `./scripts/test-home-manager.sh` で動作確認した
```

該当しない項目は `[x]` にして括弧内で理由を書く(「新規コマンドの追加なし」など)。確認できなかった項目は `[ ]` のまま残し、なぜできなかったかと何に委ねるかを書く。**通っていないものを通ったことにしない。**

## コミットとマージ

コミットメッセージは種別接頭辞をつける(`feat:` / `fix:` / `docs:` / `refactor:` / `chore:` / `ci:` / `revert:`。迷ったら `chore:`)。コミットにも PR 本文と同じ制約がかかる — Claude のフッターもセッション URL も入れない。

マージは squash。required status check は lint / gitleaks / home-manager-test の4つで、揃うまで待つ。緊急時以外は admin 権限で押し通さない。

```sh
gh pr merge <番号> --squash --delete-branch
```

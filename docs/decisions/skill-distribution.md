# 自作スキルの配布方式

**結論**: 自作スキルは Nix(home-manager)で `~/.claude/skills/` へ配るのをやめ、このリポジトリ自身をローカル Marketplace にしてプラグイン機構で配る(2026-09)。

公式スキルの採用基準と herdr の配布方式は [`agent-skills.md`](agent-skills.md) を参照。こちらは自作分の配布経路についての決定。

## 背景

自作スキルを Claude Code だけでなく Codex や Cursor でも使うようになり、「どこに実体を置き、どう各ツールへ届けるか」を決める必要が出た。`~/.claude/skills/` への手動配置では、同じスキルの実体がツールごとに散り、片方だけ古くなる。

## 検討した代替

| 観点 | Nix で `~/.claude/skills/` へ配布 | `~/.claude/skills/` への symlink | プラグイン機構(採用) |
|---|---|---|---|
| 複数ツールへ届くか | ×(配置パスがツールごとに違い、増えるたび `nix/home.nix` に分岐が要る) | ×(同上) | ○(目録に載せるだけ) |
| 環境ごとの有効/無効 | ×(配ったマシン全部に入る) | × | ○(プラグイン単位で切り替え) |
| 実体の一元化 | ○ | ○ | ○(ローカル参照なので実体は1つ) |
| 標準への準拠 | × | × | ○(Agent Plugins 1.0) |
| 導入の手数 | ○(`switch` で完結) | △(手動リンク) | △(明示実行が1回要る) |

## 選んだ理由

- **ツールが増えるほど Nix 配布が破綻する。** 配置パスがツールごとに違う(Claude Code は `~/.claude/skills/`、Codex は Marketplace 経由、Cursor は `~/.cursor/plugins/local/`)。Nix で配るならツールごとに分岐を書き足すことになる。Agent Plugins 1.0 はまさにこの問題を解くための標準で、そこに乗らない理由がない。
- **切り替えの単位を確保できる。** プラグイン由来のスキルは `skillOverrides` が効かず、**プラグイン単位でしか無効化できない**。Nix で全マシンに配ると環境ごとに外す手段が無くなる。スキルはエージェントの挙動そのものを変えるため、環境ごとに外せることには実用上の意味がある。
- **`~/.claude/` はエージェント側の領域**という既存方針と整合する。herdr が例外なのは nixpkgs がスキル本文を同梱していてバイナリとのバージョン一致が構造的に保証されるからで、自作スキルには当てはまらない。
- **構造がツール境界の説明になる。** どのマニフェストをどのツールが読むかが配置から読み取れる。

## トレードオフ

- **`home-manager switch` で完結しない。** マシンごとに `agent-plugins-setup`(`home/.local/bin/`)の明示実行が1回要る。更新時も、ローカル参照の Marketplace は自動更新が効かないため実行が必要。
- **マニフェストが3つになる。** Claude Code も Codex もルート直下の標準 `plugin.json` を読まない(Cursor と Copilot / VS Code は読む)。1つに寄せると、寄せた先を読まないツールがメタデータを黙って失う。
- **リポジトリを移動するとローカル参照が切れる。** エラーにはならず静かに読み込まれなくなるだけなので気づきにくい。`agent-plugins-setup` の再実行で復旧する。
- **有効化はマシンごとの手作業になる。** 登録しただけでは使える状態にならない。ただしこれは上記「環境ごとの有効/無効」の裏返しで、切り替えられることと引き換えの手数。

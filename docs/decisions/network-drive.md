# ネットワークドライブ連携は作らない(意図的な見送り)

## 検討した代替

- ネットワークドライブ(Z: 割り当て・NAS 等)へ自動で `cd` する連携コマンドを作る(`cdod` 等の他のクラウドストレージ連携コマンドと同様の位置付けで)

## 選んだ理由

- サーバー名・共有名は内部ネットワーク情報にあたり、「個人的なこと・特定の文脈が分かることは一切含めない」という最重要ルールに抵触しやすいため。
- sudo 必須・不通時のハング・ゴーストマウント等、挙動としても危うく、他のクラウドストレージ連携コマンド(存在チェック→親切メッセージで正常終了)ほど安全に作れないため。
- 自分専用ではない環境で一時的に作業することがあり、そうした環境に永続的な変更を残したくないため、ネットワークドライブへの自動連携のような「環境に根を張る」設定は持ち込まない方針とも合致する。
- ストレージ運用は普段からクラウドストレージ(OneDrive/iCloud/Google Drive。既存の `cdod`/`cdic`/`cdgd` 参照)を基本にしており、ネットワークドライブ自体への依存が薄い。

## トレードオフ

- 必要になったら `local.sh`(git 管理外)に自分専用の関数を書けばよい。dotfiles 本体(`home/`)には入れない。

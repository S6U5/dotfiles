# ネイティブ Windows へのサプライチェーン対策の配り方

npm / pnpm / uv のサプライチェーン対策(`ignore-scripts` / クールダウン等)は home-manager で `$HOME` に配布するが、Nix が動かないネイティブ Windows 側の npm / pnpm / uv には届かない。この穴をどう塞ぐかの決定。

## 検討した代替

- **何もしない**(対象環境は WSL / macOS / Linux なのでスコープ外として放置)
- **プロジェクト雛形に寄せる**(`templates/project/` に `.npmrc` を追加し、プロジェクトにコミットして OS 非依存にする)
- **Windows 用の自動配布機構を作る**(セットアップスクリプト等)
- **手動コピー手順を README に記載**(採用)

## 選んだ理由

- 対策ファイルは機密ゼロかつ各ツール標準の形式なので、Windows 側の標準パスへそのままコピーするだけで同じ対策が成立する。手順の記載だけで「Windows 側のパッケージマネージャが無防備」という実害を塞げ、費用対効果が最も高い。
- 自動配布機構は「Nix が使えない環境では機能しない(フォールバックを作らない)」方針([`dotfiles-distribution.md`](dotfiles-distribution.md))に反するため作らない。手動コピーの案内は配布機構ではなくドキュメントであり、方針の枠内と判断した。
- プロジェクト雛形方式は効果自体は大きいが、そのプロジェクトをクローンする他者にも `ignore-scripts` 等を強制する別の判断を伴うため、グローバル設定の穴埋めとは切り離して見送り(必要になったら別途検討)。

## トレードオフ

- 手動コピーなので追従しない。リポジトリ側の設定を変えたら Windows 側へ再コピーが必要。
- 対象ツールが増えるたびに README のコピー先表を更新する必要がある。

# ターミナルマルチプレクサは herdr をメインに、tmux はサブとして残す

## 検討した代替

| 観点 | herdr(採用・メイン) | tmux(サブとして継続) | cmux | 画面分割をターミナルエミュレータ側の機能(wezterm等)で行う |
|---|---|---|---|---|
| エージェントの完了通知への対応 | ○ | × | ○ | ×(分割機能自体にエージェント連携がない) |
| tmux 互換の操作性(キーバインド・操作感を引き継げる) | ○ | ○(本家) | ー | ー(エミュレータ依存でマルチプレクサとしての互換性は無関係) |
| 対応環境の広さ(herdr非対応環境・SSH越しなど) | ×(非対応環境では使えない) | ○ | ×(macOS版のみで WSL 非対応) | ×(SSH越しではローカルのエミュレータ機能が使えない) |
| クロスプラットフォーム対応(このリポジトリの前提: WSL/macOS/Linux) | ○ | ○ | ×(WSL 非対応のため対象外) | ー(採用するエミュレータ次第) |
| 実装言語・ライセンス | ○(Rust製、AGPL-3.0-or-later) | ○(BSD系) | ー | ー |
| 現時点の判断 | メインとして採用 | herdr 非対応環境向けにサブとして残す(併用) | 不採用(WSL 非対応のため) | 不採用(エージェントの完了通知に対応しないため) |

herdr 自体の導入方法(公式インストーラ vs 自作ラッパースクリプト)も検討したが、こちらは単純な二択で理由も一本のため表にはしない(下記参照)。

なお「画面分割をターミナルエミュレータ側の機能で行う」は、wezterm など特定のターミナルエミュレータ自体を採用するかどうかの検討ではなく、あくまで「画面分割という機能をどの層(マルチプレクサ vs ターミナルエミュレータ)に持たせるか」という論点として比較したもの。

## 選んだ理由

- herdr は Claude Code / Codex 等のエージェントの完了通知に対応しており、かつ tmux 互換の操作性(キーバインド・操作感)を引き継げる点が決め手となり、メインに採用した。tmux は herdr 非対応環境・SSH 越しなど向けにサブとして残す(併用前提であり、どちらかを廃止するわけではない)。
- cmux も同種のエージェント対応マルチプレクサとして検討したが、現時点では macOS 版のみで WSL に対応していないため、このリポジトリの前提(WSL/macOS/Linux 対応)を満たせず不採用にした。
- 導入は `packages/` に自作スクリプトを作らず、公式インストーラを直接使う方針にした(`curl -fsSL https://herdr.dev/install.sh | sh`)。macOS/Linux 対応のワンライナーで完結しており、自作でラップする価値が薄く、公式ドキュメントに従うことでメンテモード化などの変化にも気づきやすい。

## トレードオフ

- prefix キーは tmux と同じデフォルトの `Ctrl+B` のまま変更しない(両者を同時併用する想定はないため実害なしと判断)。
- 設定ファイル(`~/.config/herdr/config.toml`)をカスタマイズする段になったら、tmux と同様に home/ 自動リンク方式で管理する。

## 履歴

- (tmux → herdr をメインに、本ADR): 上記の理由により決定
- (2026-08-01: 導入方法を公式インストーラ → Nix(`nix/home.nix` の `home.packages`)に変更。Nix が基本経路になった(`package-management.md` 参照)ことに伴う見直し。nixpkgs に `herdr` パッケージが存在し(`pkgs/by-name/he/herdr`、活発にメンテナンスされ `broken` 等のフラグなし)、herdr 公式もNixを明示的に非推奨としていないため、公式インストーラを都度実行する運用から Nix 管理に切り替えた)
- (2026-08-01: 同日中に `packages/`(軽量な代替経路)自体を完全廃止し Nix に一本化。「`packages/` を選んだ場合は公式インストーラを使う」という上記の分岐は解消され、herdr は全環境で Nix 経由のみになった。判断根拠は `package-management.md` 参照)

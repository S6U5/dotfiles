# 決定の記録(ADR)

複数の選択肢から何かを選んだとき、「なぜそれを選んだか」を記録する場所。
本格的な設計書ではなく、決定1件につき1ファイル・数行程度の軽量な記録(AGENTS.md「ドキュメント」参照)。

## いつ書くか

- ツール・ライブラリ・実装方式などで複数の選択肢を検討し、明確な理由を持って1つを選んだとき
- 特に「なぜ有名な代替 Y ではなく X なのか」が非自明なとき
- まだ決定していないが、比較検討の内容が TODO.md に埋め込むには重くなってきたとき — 冒頭に **「ステータス: 検討中(未決定)」** と明記した上でここに置いてよい。決まったら通常の(決定済みの)ADR として書き直す

## 書き方

- ファイル名: `<テーマ>.md`(番号なし)。**「今の答え(採用したツール名)」ではなく「決定のトピック」で名付ける**(例: `neovim.md` ではなく `editor.md`)。後で覆る可能性がある決定ほど、探すときはツール名ではなくトピック名で探すため。逆に、決定が覆っても意味を持ち続ける技術的判断(例: 特定ツールの apt が古いので公式スクリプトを使う、等)は、そのツール名のままでよい(例: `zoxide.md`)
- 内容は以下だけ、簡潔に:
  - 検討した代替
  - 選んだ理由
  - トレードオフ(あれば)
- 代替が2つ以上あり、複数の観点で比較したい場合は、プレーンな箇条書きではなく **○/△/× の比較表**にしてよい(観点を行、代替を列にする)。単純な二択(採用 vs 不採用1つだけ)なら表にせず簡潔な文章でよい。
- 検討した代替には、厳密には同じカテゴリではない選択肢(例: 通常のエディタの比較に AI エージェントの内蔵編集機能や AI ネイティブエディタを含める、等)も含めてよい。できること・利便性の面で比較の土台になるなら、カテゴリが多少違うことを理由に除外しなくてよい。
- 過去の記録は書き換えない。決定を覆したら新しいファイルを追加するか、末尾の「履歴」セクションに時系列で追記する(本文の全面書き換えはしない)。トピック名で命名したファイル(例: `editor.md`)は、この「履歴」セクションにそのトピックの過去の乗り換え(例: Atom → VSCode → Neovim)も含めて時系列で並べてよい
- `AGENTS.md` には結論だけ書き、詳細な比較・理由はここへのリンクに逃がす

# DOTFILES_DIR の永続化方法

`home-manager switch --flake ./nix#<system> --impure` は `nix/home.nix` がリポジトリパスを
`builtins.getEnv "DOTFILES_DIR"` で解決するため(`dotfiles-distribution.md` 参照)、実行前に
`export DOTFILES_DIR=$(pwd)` が必要だった。これをシェルセッションごとに手打ちしなくて済むよう、
どこに永続化するかの決定(2026-09)。

## 検討した代替

1. **現状維持**(毎セッション手動 `export`)
2. **ブートストラップ実ファイルに追記**(`~/.bashrc` / `~/.bash_profile` / `~/.config/zsh/.zshrc` の1行ローダーに `export DOTFILES_DIR=...` を足す)
3. **`home.activation` 生成の専用実ファイル** `~/.config/shell/dotfiles-dir.sh`
4. **`local.sh` に手で書く**(README に手順として記載するだけ)
5. **`home.file`(`text`)で専用ファイルを生成**(採用。パスは案3と同じ `~/.config/shell/dotfiles-dir.sh`)

## 選んだ理由

- 専用ファイルを `init.sh` の `*.sh` 自動読み込みに乗せる形(案3・案5)なら、シェル側の変更なしで全シェルに効き、リポジトリを移動しても switch で自動追従する。マシン固有の絶対パスはリポジトリ(`home/`)に置けないので、生成が必要になる。
- ブートストラップ(案2)は nvm 等のインストーラ追記の受け皿を兼ねる設計のため、生成側から安全に**更新**できない。生成済みファイルは冪等性チェックでスキップされるので既存マシンに export 行が届かず、かといって書き換えるとインストーラの追記を壊す。3ファイルへの同期も必要になる。
- 案3と案5の比較では **home-manager の世代管理に乗る案5が勝る**: この機能を廃止するときエントリを消せば次の switch でリンクが自動掃除されるが、`home.activation` 生成の実ファイルは誰にも回収されず孤児として残る(掃除用 activation を別途書く必要がある)。既存ファイルとの衝突検知・`-b` での退避も home-manager 標準機構がそのまま使え、案3で必要だった自前の保護・バックアップ・冪等性のコードとテストが丸ごと不要になる。ブートストラップを実ファイル化した理由(インストーラの追記を受け止める。`zshrc-pollution.md` 参照)は、追記してくるツールが無いこのファイルには当てはまらない。
- 案4は自動化されず、リポジトリ移動時に手動更新が必要で、書き忘れると案1と同じ。

## トレードオフ

- 読み取り専用の Nix store シンボリックリンクになるが、このファイルに書き込むツールは想定されないため実害なし。
- マシン固有の絶対パスが Nix store(とリンク先の `$HOME`)に置かれるが、いずれもローカルのみでリポジトリにはコミットされないため、機密ゼロ方針とは矛盾しない(`local.sh` と同じ扱い)。

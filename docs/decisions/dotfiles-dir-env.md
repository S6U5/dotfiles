# DOTFILES_DIR の永続化方法

`home-manager switch --flake ./nix#<system> --impure` は `nix/home.nix` がリポジトリパスを
`builtins.getEnv "DOTFILES_DIR"` で解決するため(`dotfiles-distribution.md` 参照)、実行前に
`export DOTFILES_DIR=$(pwd)` が必要だった。これをシェルセッションごとに手打ちしなくて済むよう、
どこに永続化するかの決定(2026-09)。

## 検討した代替

1. **現状維持**(毎セッション手動 `export`)
2. **ブートストラップ実ファイルに追記**(`~/.bashrc` / `~/.bash_profile` / `~/.config/zsh/.zshrc` の1行ローダーに `export DOTFILES_DIR=...` を足す)
3. **activation 生成の専用ファイル** `~/.config/shell/dotfiles-dir.sh`(採用)
4. **`local.sh` に手で書く**(README に手順として記載するだけ)

## 選んだ理由

- ブートストラップ(案2)は nvm 等のインストーラ追記の受け皿を兼ねる設計のため、activation 側から安全に**更新**できない。生成済みファイルは冪等性チェックでスキップされるので既存マシンに export 行が届かず、かといって書き換えるとインストーラの追記を壊す。3ファイルへの同期も必要になり、リポジトリを移動したときに古いパスが残る。
- 専用ファイル(案3)ならファイル全体を activation が所有できるので、**switch のたびに無条件で再生成**してよく、リポジトリ移動にもパスが自動追従する。`init.sh` の `*.sh` 自動読み込み(アルファベット順ループ)にそのまま乗るため、シェル側の変更も不要。
- 案4は自動化されず、リポジトリ移動時に手動更新が必要で、書き忘れると案1と同じ。

## トレードオフ

- home-manager 生成の管理外実ファイルがもう1種類増える(ブートストラップ3ファイル+これ)。ファイル冒頭のコメントで生成元と「手で編集しない」旨を明示して緩和。
- マシン固有の絶対パスが `$HOME` 配下の平文ファイルに置かれるが、リポジトリにはコミットされないため機密ゼロ方針とは矛盾しない(`local.sh` と同じ扱い)。

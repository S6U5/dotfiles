# dotfiles-update は既定で main に切り替えて更新する

`dotfiles-update`(`update.sh`)は、いまいるブランチを pull して反映していた。作業ブランチのまま打つと、マージ前の途中の状態がマシンに反映され、そのまま使い続けることになる。

| 観点 | 今のブランチを pull(前の動き) | いつも main | 既定は main、`--current` で今のブランチ(採用) |
|---|---|---|---|
| マシンが main の状態にそろう | ×(打ったときのブランチ次第) | ○ | ○ |
| 作業ブランチの内容を試せる | ○ | ×(`dotfiles-switch` を手で打つしかない) | ○(`--current`) |
| いつもの1語で済む | ○ | ○ | ○ |

- 「main は常にそのまま使える状態を保つ」(AGENTS.md のブランチルール)ので、更新の既定は main にする。
- 使うブランチは origin の既定のブランチ(clone したときの `origin/HEAD`)。無ければ `main`。フォークなどで既定のブランチ名が違っても動く。
- 未コミットの変更があれば、切り替える前に中断する(前と同じ)。切り替えたら、元のブランチに戻るコマンドを表示する。

## トレードオフ

- 作業ブランチにいるときに打つと、ブランチが main に変わる。作業の続きをするには、表示されたコマンドで戻る必要がある。
- detached HEAD のときに `--current` を付けると、どのブランチを pull するか決まらないので中断する。
